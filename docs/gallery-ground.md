# Approved gallery ground — Optical Marginalia

The Dark and Light Canvas options use the owner's selected photographic field from `gallery-ground-1843.json`, not the earlier per-URL random glyph scatter. Blank was subsequently retired by the owner: the Canvas control offers Dark and Light only, Dark is the gallery default, and stored legacy Blank preferences migrate onto it. Every gallery therefore paints the field, and strip frames keep their 10px margins so photographs sit a gutter apart over the artwork. Existing per-gallery canvas preferences, photo staging, the 10px margins, curtain behavior, controls and ad plates are otherwise unchanged. The owner separately authorized stronger inks and the same texture on app surfaces.

## Frozen source

`assets/gallery-ground/approved.project.json` retains the uploaded file byte-for-byte. SHA-256: `16c19ef3be3c830d7ef5a8f8d0fb27c670c1995a765d96667e4cbec9f072565d`. The approved recipe is seed1843, 1024×1024 logical pixels, dense, 3px rounded strokes, 20px minimum gaps and scale0.85–1.15. It contains 24 original hand-authored photographic motifs and **80 valid placements**; the generator reported ten requested motifs unplaced. Those 80 accepted placements are the design selected by the owner: they must not be repacked to reach 90.

`app/assets/gallery-ground.ts` contains only their baked paths, wrapped edge/corner copies, metadata and source checksum: 92 wrapped groups, 258 paths. It is a static data export produced from the validated source project's tile export, preserving the exact four-decimal path coordinates. It uses a TypeScript module because the HonoX dev route intercepted the equivalent JSON module request as a gallery URL; production builds accepted JSON, but real browser hydration exposed the dev-only 404. The module-format correction was verified to preserve the exact serialized data. Neither app startup nor viewport changes rerun layout. The procedural illustrator, model SDK, Sharp and project validation runtime are **not** app dependencies; they were used only during preparation. No root dependency or core platform boundary changes.

## Shared rendering

`app/islands/SeededDoodleBackground.tsx` keeps the existing shared integration point used by the web gallery, Capacitor native gallery and desktop gallery. Its historical filename remains to avoid changing consumers. The SVG is inert, aria-hidden and decorative at z-index0 inside the stage. Following the owner's 21 November density choice, it repeats a `userSpaceOnUse` pattern at exactly **256 CSS pixels**. One `scale(0.25)` group maps the unchanged 1024-unit artwork into that repeat: source 3-unit strokes become 0.75 CSS pixels and source 20-unit packing gaps become 5 CSS pixels. There are four repeats per direction, or sixteen times as many per screen area as the original 1024px presentation. The root has no scaling viewBox; resizing only exposes more or less of the same fixed texture. URLs, query strings, navigation and device-pixel ratio do not recompose it. Each mounted SVG has its own paint-server ID, so separate viewers cannot resolve another instance's palette. Photograph bytes and boxes never participate in this vector-only transform.

The stronger Dark pairing uses canvas `#101010`, ink `#484848`; Light uses canvas `#e9e5dc`, ink `#aaa59b`. Both inherit the ink through `currentColor`, sharing every path. App chrome's `html.light` switch cannot recolor a gallery's chosen canvas. The field uses no photographs, bitmap, filter, clip to a photograph, blur, remote fetch or event handler; existing media bytes and image boxes are untouched. The landing page's embedded demo keeps its existing field exclusion.
