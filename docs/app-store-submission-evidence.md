**Repository:** `thecont1/manorama`
**Scope:** documentation-only handoff for the iOS App Store path, RevenueCat, and AdMob.
**Evidence basis:** current files in this worktree plus the plans and runbooks linked below. This document does not verify an Apple, RevenueCat, AdMob, device, or store dashboard state.

## How to read this handoff

`Repository evidence` means an autonomous reviewer can inspect the cited file and symbol. `Owner/device/dashboard gate` means Mahesh must perform the action in Apple, RevenueCat, AdMob, Xcode, or on physical hardware and attach the requested proof. A repository implementation is not treated as shipped functionality until its corresponding owner/device proof exists.

The current planning context is [`native-launch-plan.md`](./native-launch-plan.md), the owner-only sequence is [`owner-setup-runbook.md`](./owner-setup-runbook.md), and the billing implementation contract is [`revenuecat-capacitor.md`](./revenuecat-capacitor.md).

## Autonomous repository validation versus owner gates

### Autonomous repository validation

The following can be checked without Apple, RevenueCat, AdMob, a dashboard login, or physical hardware:

- Inspect the exact symbols and files in the matrix above; in particular, the RevenueCat adapter, webhook route/helper, plist entries, privacy manifest, `app-ads.txt` route, and their existing unit tests.
- Run `bunx tsc --noEmit`, `bun test`, `bun run build:native`, `bun run build`, and `bunx cap sync` as repository/build checks, as prescribed by [`revenuecat-capacitor.md`](./revenuecat-capacitor.md:157-167). These commands do **not** prove App Store submission, dashboard configuration, signing, or device behavior.
- Run `git diff --check` after this documentation-only change.

### Owner/device/dashboard gates

Only the owner can verify Apple agreements and records, signing/archive/TestFlight upload, App Review metadata and notes, App Privacy questionnaire submission, RevenueCat products/offering/paywall/Customer Center/webhook settings, AdMob app/ad units and store association, domain publication/serving status, sandbox purchase/restore, physical display checks, reviewer access, and manual release. Keep credentials, `.p8` files, webhook secrets, demo-account passwords, and private gallery links out of this repository.

Until those gates have dated proof, the handoff status remains **pending**. In particular, repository code or a plan is not evidence that an encrypted vault, offline thumbnails, global view, native ad plate, purchase, review submission, or live release exists in the binary.
